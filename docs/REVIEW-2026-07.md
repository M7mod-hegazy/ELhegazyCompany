# ElHegazi — Site review, image brief, and UX direction

Reviewed against a **production build** (`next build` + `next start`), Chromium, at
1440×900 (desktop) and 390×844 (mobile), Arabic RTL locale. Build passes clean —
every problem below is a runtime/visual one, not a compile error.

---

# PART 1 — Bugs and rough edges

Ranked by how much damage each one does. File references are exact.

## 1.1 — Blocker: every section heading is bigger than the page headline

**This is the single biggest reason the site reads as unfinished.**

`src/app/globals.css:50-60` overrides Tailwind's `--text-3xl`, `--text-4xl` and
`--text-5xl` with a fluid clamp scale — but never defines `--text-6xl`. So:

| Element | Class | Actual size @1440px |
|---|---|---|
| Hero `<h1>` | `md:text-6xl` | **60px** (Tailwind default — not overridden) |
| Diagnostic `<h2>` | `md:text-5xl` | **126px** |
| Counter `<h2>` | `md:text-5xl` | **126px** |
| Grid `<h2>` | `md:text-5xl` | **126px** |
| Tracker `<h2>` | `sm:text-4xl` | **92px** |
| CTA `<h2>` | `sm:text-4xl` | **92px** |

Every `h2` is 1.5×–2.1× the size of the `h1`. Consequences visible on screen:

- The Diagnostic heading wraps to three lines and eats a full viewport.
- The home CTA heading **overflows its own section** — `statement1`
  ("إحنا مش بنعمل إعلانات وبس —") is pushed above the section top and is never seen.
  Only `statement2` renders. (`src/components/home/HomeCta.tsx:98-105`)
- Marketing pillar headings are clipped by the fixed navbar.

**Fix:** add `--text-6xl` / `--text-7xl` to the `@theme` block and re-tier the
headings, or drop the section headings one step. Suggested scale:

```css
--text-4xl: clamp(2.25rem, 1.60rem + 2.60vw, 3.50rem);   /* section h2 */
--text-5xl: clamp(2.75rem, 1.80rem + 3.60vw, 4.50rem);   /* page h1     */
--text-6xl: clamp(3.25rem, 2.00rem + 4.80vw, 5.75rem);   /* hero h1     */
--text-7xl: clamp(3.75rem, 2.10rem + 6.40vw, 7.00rem);   /* reserved    */
```

Mobile is unaffected (all clamps bottom out), so this is a desktop-only defect —
which is where most B2B buyers evaluate you.

## 1.2 — Blocker: the Instruments section shows panel 3 first

`src/components/home/InstrumentsSection.tsx:56-80`

Panel transforms are written **only inside `useMotionValueEvent`**. Before the
first scroll event inside the track, no panel has any inline style, so all three
sit at `absolute inset-0` with no transform and the **last one in DOM order paints
on top**. A visitor arriving at that section sees *marketing* (`٣`) before they
ever see *POS* (`١`).

**Fix:** apply the initial state in a `useLayoutEffect` on mount (and on resize),
using the same function the scroll handler calls.

---

## 1.3 — The video fallback letterboxes instead of filling

`src/components/film/AmbientFilm.tsx:181-200`

When `useVideoAllowed()` returns `false`, no `src` is ever attached and the
`<video poster>` is all the user sees. Chrome renders that poster **letterboxed**,
not covered — confirmed on the desktop Instruments panels (black bands top and
bottom of the right column) and on the mobile hero.

Two separate problems here:

**(a) The gate is too aggressive and never re-evaluates.**
`src/lib/video/capabilities.ts:37` blocks video when
`navigator.connection.downlink < 1.0`. That value is a *rolling estimate* and is
routinely under 1.0 during initial page load and on Egyptian mobile networks. The
check runs once in a mount effect and never runs again, so a user whose connection
recovers stays on posters **for the whole session**. In this test browser
`downlink` reported `0.4`, so all 8 videos on the home page never loaded.

**Fix:** re-check on `navigator.connection`'s `change` event, and raise the bar to
`downlink < 0.5` / `effectiveType === 'slow-2g'` only.

**(b) The poster path needs to be a real layer.**
Don't rely on the `poster` attribute for the fallback. Render a `next/image`
`fill` + `object-cover` underneath the `<video>` and let the video paint over it.
That fills correctly, gets AVIF/WebP conversion, and gives you a proper LCP element.

## 1.4 — Every primary CTA takes a server redirect

`src/components/site/Navbar.tsx:68` and `:126` → `href="/start"`
`src/components/site/CtaBand.tsx:28` → `href={"/" + locale + "/start"}`

`/start` was deleted; `next.config.ts:20` redirects it to `/contact`. So it isn't
a 404 — but:

- The nav "ابدأ مشروعك" button and the CtaBand primary button both cost a
  **308 round-trip before anything renders**. Redirected routes are not prefetched,
  so the most important button on the site is the slowest thing on it.
- `CtaBand` uses a raw `<a>` instead of the i18n `Link`, forcing a **full document
  reload** — the app shell, fonts, Lenis and the preloader all restart.

**Fix:** point all three at `/contact` and use `Link` from `@/i18n/navigation`.

**Same class of bug, worse:** `src/components/world/Pricing.tsx:18`,
`src/components/world/DownloadCenter.tsx:27` and
`src/components/marketing/MarketingSections.tsx:366` link to
`/order?product=…&plan=…`. That redirects to `/contact`, which **ignores the query
string entirely**. A visitor who clicks "اطلب الخطة" on a specific pricing tier
lands on a blank generic contact form with no idea which plan they picked.

**Fix:** link to `/contact?product=…&plan=…` and have `ContactForm` pre-fill the
message from those params.

## 1.5 — The design system's two headline rules are broken site-wide

`docs/REBUILD-PLAN.md` §3 locks two rules that are what make this look engraved
rather than generic-dark-SaaS:

> Zero border-radius anywhere except the seal circle.
> No `backdrop-filter` / glassmorphism anywhere.

Current state: **107 `rounded-*` usages** across 27 files and **10 `backdrop-blur`
usages**. The most damaging, because they sit next to compliant components:

| File | Violation |
|---|---|
| `site/Navbar.tsx:69, :128` | `rounded-full` CTA pill + `backdrop-blur-lg` mobile menu |
| `site/CtaBand.tsx:13, :29, :37` | `rounded-3xl` card + two `rounded-full` pills |
| `world/ShotFrame.tsx:46, :88` | `rounded-xl` frame, `rounded-lg` + `backdrop-blur-sm` |
| `marketing/MarketingSections.tsx:168` | `rounded-3xl` pillar frames |
| `fx/SoundToggle.tsx:73` | `rounded-full` + `backdrop-blur` |

The visible result on `/ar/projects`: sharp-cornered project panels sitting
directly above a soft rounded CTA card with pill buttons. It reads as two
different websites.

## 1.7 — Fixed navbar occludes every section kicker

The header is `fixed` and ~76px tall. Sections open with `py-24` / `pt-[10svh]`,
which is roughly the same height, so when a section lands at the top of the
viewport its **kicker disappears behind the navbar**. Confirmed on Diagnostic
("٣ أسئلة بس"), Counter, and all four marketing pillars.

**Fix:** add `scroll-margin-top: 6rem` on sections and raise the opening padding
past the header height.

# PART 2 — Images: what has to be real, and the prompts

Three different problems here. Only one of them is solved by generating images.

## 2.A — Product screenshots: capture, do not generate

`public/shots/` was deleted. `ShotFrame` (`src/components/world/ShotFrame.tsx`)
therefore renders a dashed placeholder box with the literal file path printed
inside it on **every POS and e-commerce feature section**. Visitors see
`/shots/pos/pos-checkout.png` where the product should be.

These are screenshots of software you actually own (`d:\code\retailer`). They must
be captured, not invented — a generated fake POS screen is both obvious and a
credibility risk. **32 files, all `.png`:**

**`public/shots/pos/` (17)** — `pos-checkout`, `shift-close`, `treasury-ledger`,
`stock-transfer`, `physical-count`, `reports-center`, `owner-dash`, `whatsapp-crm`,
`print-designer`, `receipt-80`, `backup`, `mod-restaurant`, `mod-gold`,
`mod-serials`, `mod-pharmacy`, `mod-clothing`, `mod-repair`

**`public/shots/ecommerce/` (15)** — `ec-storefront`, `ec-room-planner`,
`ec-3d-viewer`, `ec-checkout`, `ec-payment-methods`, `ec-dashboard`, `ec-reports`,
`ec-products`, `ec-mobile`, `mod-fashion`, `mod-electronics`, `mod-food`,
`mod-furniture`, `mod-books`, `mod-services`

**Capture spec — follow this exactly or they won't sit together:**

- `device: "app"` → 1920×1200, dark theme, Arabic UI, no OS chrome (the frame is
  drawn by `ShotFrame`).
- `device: "browser"` → 1920×1200, no browser chrome.
- `device: "phone"` → 1170×2470 (iPhone-class), Arabic UI.
- `device: "thermal"` → 576×1024, white receipt on a near-black background.
- `device: "a4"` → 1240×1754.
- **Seed the database with believable Egyptian data first**: real product names in
  Arabic, EGP prices, Egyptian phone numbers, today's date. Screenshots of an empty
  or `test test test` database are worse than placeholders.
- Redact nothing by blurring — change the data instead.
- Export PNG, then run through `squoosh`/`sharp` to WebP if you switch `ShotFrame`
  to `next/image` (recommended — it currently uses a raw `<img>`, `:67`).

## 2.B — Marketing pillars: use your own work, not abstract shapes

`src/components/marketing/MarketingSections.tsx:166` is commented
*"Abstract, art-directed visual per pillar — no screenshots needed."* On screen the
"تصميم وإبداع بصري" pillar is **nine empty gradient rectangles**. A design agency
showing blank boxes where its design work goes is the worst thing on the site.

These should be a **contact sheet of real deliverables you have already made**:
your own ad creatives, carousels, reels covers, product photography, brand boards.
Four composites, `public/marketing/pillar-<id>.jpg`, 1600×1200, on the ink ground.

If you genuinely have nothing to show yet, produce the work for **your own furniture
shop** first — that is literally the site's thesis ("we are the first customer of
everything we build").

## 2.C — Editorial / brand imagery: these you can generate

House style for every prompt below — keep it identical so they read as one shoot:

> Cinematic still, near-black warm ink background (#0A0A0B), single warm brass key
> light from one side, deep falloff, no colour cast other than champagne brass
> (#C9A86A) and deep oxblood (#5A1F1B). Shallow depth of field, 50mm, subtle film
> grain, museum-catalogue restraint. No text, no logos, no glass/frosted effects,
> no lens flare, no HDR look.

# PART 3 — Home page: UI/UX direction

The material here is genuinely strong — the copy is specific and confident, the
palette is disciplined, and the Counter and Grid photographs are excellent. The
problems are **information sequencing** and **dead space**, not taste.

## 3.1 — The hero currently states a thesis but never states the offer

A first-time visitor reads *"بنشغّل محلاتنا بنفس اللي بنبيعهولك"* and a supporting
line, then has to scroll blind. The three things you sell are named only inside a
paragraph.

**Add an offer rail directly under the CTAs** — three hairline cells, full width,
sitting on the bottom edge of the hero:

```
┌──────────────────────┬──────────────────────┬──────────────────────┐
│  نقاط البيع           │  المتجر الإلكتروني    │  التسويق الرقمي       │
│  كاشير ومخزون         │  متجرك أونلاين        │  إعلانات ومحتوى       │
│  ‹hairline›           │  ‹hairline›           │  ‹hairline›          │
└──────────────────────┴──────────────────────┴──────────────────────┘
```

- Zero radius, 1px `brass/15` dividers, no fill.
- On hover: the cell's accent hairline (slate / oxblood / brass) draws in from the
  inline-start edge over 240ms. Nothing moves, nothing scales.
- Each cell links to its product page. This gives the hero a **third tier of
  navigation** and answers "what do you actually sell" in the first viewport.
- **Mobile:** stack to a single 3-row list, 56px rows, still hairline-ruled. It
  costs ~170px and it is the highest-value 170px on the page.

Also darken the hero scrim (`HomeHero.tsx:83`) so the seal stops competing, and
give the scroll cue (`اسحب`) real contrast — it's currently `brass/50` at 10px and
effectively invisible.

## 3.2 — Give the Diagnostic a visible spine

It's the best idea on the page and it's presented as a plain form in a box.

- Replace the text-only "1 من 3" with **three hairline segments** that fill brass as
  you answer. Same `rule-seal` language, so it belongs.
- Reveal the answer buttons with a **50ms stagger** — the questions already animate,
  the answers appear all at once and feel static.
- On the result card, **stamp the real seal asset** (Part 2.C #1) at ~20% opacity
  behind the price/duration block instead of the two nested CSS circles at
  `DiagnosticSection.tsx:242-246`. This is the payoff moment; make it feel like a
  document that has been issued.
- Add a third action next to WhatsApp and the product link: **"ابعتلي التفاصيل على
  الإيميل"**. Not everyone wants to open WhatsApp from a laptop.
- **Mobile:** move the result card's two actions into a full-width stacked pair with
  56px height. Currently they wrap awkwardly.

## 3.3 — Make the Counter and Grid hotspots discoverable

Both sections hide their entire interaction behind a 12px dot at 55% opacity.

- Give each dot a **persistent 1px brass ring plus a slow 3s pulse** (already coded
  for Counter, missing for Grid), and raise the resting opacity to 100%.
- On desktop, reveal **all labels at low opacity** on section enter, then fade them
  back after 1.5s. The user learns there are labels without having to guess.
- Move the Grid legend **out of the photograph** — put it in a hairline row directly
  beneath the tray. At `y: 95%` it currently sits on top of the objects.
- **Mobile:** dots are 40–44px hit targets already (good). But the Counter tooltip
  is a fixed 224px panel that runs off-screen for right-side hotspots. Switch to a
  bottom sheet on `< 640px`: tap a dot → a hairline panel slides up from the bottom
  edge, full width, with a close affordance.

## 3.4 — Fix the Instruments panels, then let them breathe

Beyond the initial-state bug (1.2):

- The copy column is `px-12` with right-aligned Arabic, leaving ~100px of dead space
  on the inline-end side. Constrain the text to `max-w-[46ch]` and let it sit against
  the video edge — the gutter should be on the outside, not between the two halves.
- The `١ ٢ ٣` numeral at `text-bone/10` and 126px is both clipped and invisible.
  Either commit to it (drop to 72px, raise to `/16`, give it its own row above the
  kicker) or cut it. Chanel's rule applies: this is the accessory to remove.
- The stat card overflows its own border. Set the number to `text-2xl` and give the
  card `py-5`.
- Fix the `→` arrow direction (1.6).
- **Mobile:** the panels currently render as a plain vertical sequence. Keep that —
  don't port the sticky stack. But add the accent hairline on the inline-start edge
  of each panel so the three read as a set.

## 3.5 — Close the gaps

- ~200px of empty black between the Tracker and Selected Work, and again before the
  CTA. Either put the tracker band image (Part 2.C #7) behind the rail, or cut the
  section padding from `py-24` to `py-16`.
- Bring the CTA copy block **inside `max-w-7xl`** instead of pinning it to
  `right: 0`. It's the last thing on the page; it should land on the same grid as
  everything above it.
- **Mobile — the highest-value single addition to the whole site:** a **sticky bottom
  action bar** below ~640px. Two cells, hairline-divided, ink background,
  56px tall, appearing after the hero leaves the viewport:
  `[ كلّمنا واتساب ]  [ ابدأ مشروعك ]`.
  Right now a mobile visitor has no CTA at all between the hero and the footer —
  that is ~7,000px of scrolling with no way to act. Add `padding-bottom` to the
  footer so it doesn't sit under the bar.

# PART 4 — Projects page: UI/UX direction

Currently: video hero → two near-black panels → rounded CTA card → footer. For the
page whose entire job is proof, it proves nothing. Three of its four screens are
empty space.

## 4.1 — Rebuild the collapsed panel to carry information

The expanding-panel idea is right; the collapsed state is throwing away every piece
of information it has.

```
DESKTOP — collapsed panel (each ~200px wide, 100svh tall)
┌──────────────────┐
│                  │  ← cover at opacity 0.55, no extra scrim
│                  │
│                  │
│                  │
│   ▁▁▁▁▁▁▁▁▁▁▁   │  ← hairline, brass/20
│   ٠١             │  ← mono numeral, horizontal, Arabic-Indic
│   أثاث النور      │  ← client, 15px, horizontal
│   تسويق · ٢٠٢٤   │  ← category · year, mono 11px, bone-muted
│   ▁▁▁▁▁▁▁▁▁▁▁   │
│   +١٨٠٪ مبيعات   │  ← the headline metric, brass
└──────────────────┘
```

Every change here is doing one job:
- **Kill the vertical rotated Arabic** (`ExpandingPanels.tsx:150`). Horizontal text
  in a 200px column is perfectly readable at 15px and rotated Arabic is not readable
  at any size.
